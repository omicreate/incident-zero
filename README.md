# インシデント・ゼロ

セキュリティ事件を、守る側か攻める側で体験する一人用のブラウザゲーム(試作)。
実在の公開事件を下敷きにした架空の5舞台 × 攻守 × 3難易度。ブラウザだけで動き、サーバ処理はない。

| 舞台 | 下敷きにした公開事件 |
|---|---|
| 病院 | 半田病院ランサムウェア(2021) |
| 年金 | 日本年金機構 情報流出(2015) |
| 港 | 名古屋港 システム停止(2023) |
| 送金詐欺 | ディープフェイク会議による送金詐欺(2024・香港) |
| 電力 | ウクライナ電力網攻撃(2015) |

## 安全の約束(必ず守る)

- 実際に使える攻撃の手順は書かない。すべてゲーム内の抽象化した判断として扱う。
- 攻める側は、守る側の弱点を裏から照らすためにある。
- 技術名(MITRE ATT&CK の ID など)は、概念・効く対策・公開された出典とセットでだけ出す。
- 端末ログ風の表示は演出で、実在のコマンドではない(画面にも明記)。

## 構成

```
public/index.html   ゲーム本体(HTML・CSS・JS を1枚に収めている)
public/bg/*.jpg     舞台ごとの背景(暗く沈めて、文字が主役)
public/404.html     見つからないとき
wrangler.jsonc      Cloudflare Workers の配信設定(静的ファイルのみ)
tools/check.mjs     分岐と演出データの整合チェック(依存なし)
docs/art-direction.md  画像の演出方針(採否の基準)
```

データは `public/index.html` の中で、`const SCENARIOS` から `/* ====== 状態 ====== */` の間にまとまっている。
台本は `SCRIPTS`(キーは `舞台:側`)、演出は `TERM`・`ADVISOR`・`CUT`・`GATE`・`STEP_TECH`(キーは `舞台:側:場面`)、
結末の専門解説は `TECH`(キーは舞台)。

## 確かめ方

```
node tools/check.mjs
```

選択肢の行き先・終端の結末キー・全場面への到達・演出データのキー・専門解説の出典を確かめる。
GitHub Actions でも push と PR のたびに同じものが走る。

## 公開の手順(一度だけ・omi が行う)

1. この変更を main に取り込む
2. Cloudflare のダッシュボード → Workers & Pages → Create → GitHub のリポジトリを読み込む
3. `omicreate/incident-zero` を選び、ルートディレクトリは空欄(リポジトリ直下)のまま Deploy
4. 表示された `*.workers.dev` の URL を開いて遊べるか確認
5. プレビューブランチのビルドはオフにする(ai-kiban と同じ理由)

以降は main に push するたびに Cloudflare が自動で公開する。API キーも支払い情報も使わない。
検索エンジンには載らないよう `noindex` を付けてある。広く公開するときに外す。

## 完了条件

- `*.workers.dev` でゲームが遊べ、5舞台の背景が表示される
- `node tools/check.mjs` が CHECK PASS
- 支払い情報は未登録のまま(無料枠を超えたら止まるだけ)

## 失敗したとき

- ビルドが失敗:ルートディレクトリが空欄(リポジトリ直下)か確認する
- 背景が出ない:`public/bg/` が配信されているか、URL 末尾の `/bg/hospital.jpg` を直接開いて確かめる
- 元に戻す:Cloudflare の該当アプリを削除する(リポジトリはそのまま残る)
